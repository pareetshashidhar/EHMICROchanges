Academic Cybersecurity Micro Project Overview

SecureUpload Inspector is a file upload security and validation system engineered to address one of the most critical web application security vectors: untrusted file ingestion. According to the OWASP Top 10 and CWE-434 (Unrestricted Upload of File with Dangerous Type), insecure file uploads often lead to Remote Code Execution (RCE), Server-Side Request Forgery (SSRF), Denial of Service (DoS), and directory traversal attacks.

Multi-Vector Inspection Architecture

This system implements defense-in-depth through five concurrent validation layers:

  1. Cryptographic Integrity: Incremental 64KB chunked SHA-256 calculation for non-blocking stream digestion and forensic fingerprinting.
  2. Filename Sanitization & Traversal Defense: Rejection of path traversal sequences (.., /, \), null bytes (\x00), and executable double extensions (e.g., .pdf.exe).
  3. Magic Byte Signature Verification: Low-level inspection of file headers (PDF %PDF-, PNG 8-byte signature, JPEG SOI FF D8 FF, cautious text heuristics).
  4. MIME Cross-Validation: Identifying discrepancies between client-declared Content-Type headers, filename extensions, and genuine byte signatures.
  5. Deterministic Policy Engine: Rule-based evaluation delivering ACCEPTED, REJECTED, or REVIEW_REQUIRED decisions alongside an auditable heuristic risk score.
Mandatory Academic Security Assertion: File validation confirms structural compliance with file format specifications and organizational upload policies. It does not claim or guarantee that a validated file is malware-free. Sophisticated exploits (such as PDF JavaScript payloads, font vulnerabilities, or stenographic polyglots) can reside inside structurally valid files. True defense requires supplementary sandboxed dynamic analysis and runtime privilege separation.
